## 一、为什么必须做这一轮

此前全部结论建立在 12 份**合成样本**上（排版规整、字体单一、无反光褶皱），
命中率 100% —— 这属于开卷考试。真实报告才是闭卷，
而评委关心的恰恰是「你这套东西在真实材料上到底行不行」。

第一次实测结果很难看：

| 指标 | 合成样本 | 真实报告（初始） |
|---|---|---|
| 解析出的行数 | 106 | 13 |
| 字典命中率 | **100%** | **15%** |
| 判定可用率 | 100% | 100% |

差距全部出在版式，而不是算法。

## 二、定位到的四个真实版式问题

### 坑 3：行首带序号 → 整行丢失

真实报告常印成 `3淋巴细胞计数  1.48`，首字符是数字。
原正则要求指标名首字符非数字，于是**整行匹配不上直接丢掉**。
→ 允许 name 前有一段可选序号；同时加「至少含 2 个汉字」的护栏，
避免 `4.00~10.00...` 这类被切成垃圾名。

### 坑 4：表头与抬头被当成指标

`独墅湖科教创新区医院化验报告单` 被解析成名为"医院"的指标。
→ 噪声词黑名单 + 汉字数下限。

### 坑 5：数值与参考区间分两行

真实报告常见版式是「名称 数值」换行再「参考范围 单位」，
原解析器只在同一行找区间，于是**拿不到区间就判不了高低**。
→ 本行无区间时，去看下一行是否以区间开头（取行首第一个区间）。

### 坑 6：弱图几乎读不出字

`github_bloodtest_6` 原图只 OCR 出 **17 个字符**，`bloodtest_3` 只有 81 个。
→ 自适应重试：产出低于 200 字符时，灰度 + 自动对比度 + 放大 1.5 倍再跑一次，取更好的那份。
实测 1.5x 优于 2.0x（拉太大笔画发虚）。**清晰件前后几乎无变化（842→843），
所以只在"快失败"时触发，不无差别预处理。**

## 三、字典按真实报告补齐

真实报告列了 22 项血常规，字典缺的是五分类的绝对值与血小板三项：

- 中性粒细胞计数 / 淋巴细胞计数 / 单核细胞计数 / 嗜酸性粒细胞计数 / 嗜碱性粒细胞计数
- 单核细胞百分比 / 嗜碱性粒细胞百分比
- 血小板压积 / 血小板分布宽度 / 平均血小板体积

另外补入真实报告里出现的倒装名与 OCR 误认形式：
`红细胞平均体积`、`平均血红蛋自`（"白"被认成"自"）、`平均血红蛋自浓度`。

字典：41 → **51 条**。

## 五、仍然存在的短板（如实记录）

1. **双栏排版仍是最大瓶颈。** 1/4/5/7 是同一份报告的竖版双栏照，
   OCR 会跨栏读（一行里挤进 `11嗜碱性粒细胞百分1.00 10嗜酸性粒细胞百分4.40…`），
   每份只解析出 2 行。这是此前就记录在案的 known limitation，
   本轮未解决——列分隔阈值在合成样本上验证过会误伤单栏表，贸然加会全面退化。
2. **8 张里有 2 张是拍摄质量很差的照片**（报告在画面里占比小、偏暗），
   即使预处理后也只能救回 1–2 行。产品侧靠拍摄引导提示规避，不做过度承诺。
3. **未命中清单里仍有 OCR 碎片**（`董薇`、`孟丁`、`蛋白瓜`、`馥城度`），
   是人名/表头碎片被当成指标行。当前靠噪声词 + 汉字数过滤挡掉大部分。

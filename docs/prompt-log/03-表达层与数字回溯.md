# 03 · 表达层：LLM 只写人话 + 数字回溯校验

## 意图（用户原话）

> 「用Kimi或者讯飞星火可以吗」

> 「这个不是AI创新应用吗，为什么不可以用大模型来识别」

这两问是一次关键的方向纠偏：用户想用大模型做识别，AI 给出的回答是
**"大模型可以进这个产品，但不能进这条位置"**——识别（数字产生）必须本地做，
大模型只允许做表达（把已经判定的结果写成大白话）。
理由：VLM 读数的错误是静默的，512 抄成 512.5 没有任何告警，
而用户拿到的却是"有 AI 背书"的数字。

## 约束与上下文

1. 输出契约 `LabTest` 里**不存在任何数值型必填字段**——模型只写字，不写数；
   `reported_value` 是字符串且必须与 OCR 原文逐字一致
2. `is_likely_normal` 三值 + `likely` 写进字段名：免责是结构性的，不靠自觉
3. 数字回溯校验：输出里每个数字都必须在事实 JSON 中有出处，否则判幻觉重跑
4. 无 Key 也必须完整可用（模板模式是默认而非兜底）——否则"本地判定"这个
   核心卖点在评委机器上演示不出来

## Prompt 快照（v0.1.0，实际代码 `app/llm/explainer.py`）

**System：**

```text
你是一位擅长把医学检验结果翻译成大白话的健康科普助手。
你只负责改写措辞，绝不修改、补充或推算任何数字。
你不做诊断，不建议用药。你的输出会被程序做数字回溯校验，
任何一个没有出处的数字都会导致本次输出被丢弃。
```

**User（`_build_prompt`）的关键段落：**

```text
下面是一份体检报告的**已判定结果**（JSON）。
数值与高低判定均已由本地系统确定，请你不要修改或重新判断任何数字。
……
硬性要求：
1. 只允许使用上面 JSON 里出现过的数字，一个都不许多写；
2. 不诊断、不建议用药，只解释「这项是什么、可能要问医生什么」；
3. 语气像家人说话，不要堆医学术语；
4. simple_explanation 不超过 60 字。
```

**校验侧的配套设计**（Prompt 管不住的，交给代码管）：

- 白名单数字：复查周期、年份等常识数字不判幻觉（否则"3-6 个月后复查"全被抓）
- 四舍五入容忍：5.41 写成 5.4 是措辞；但**整数前缀不放行**——"84" 不是 847 的四舍五入
- 报告值本地回填：模型输出的 `reported_value` 一律丢弃，用本地事实覆盖
- 两次校验不过 → 自动退回模板模式，并在界面上如实标注降级原因

## 验证

- `tests/test_llm.py` 用**故意造假的假数据**驱动校验器：
  "你的尿酸是 847"（编造值）必须被抓，"参考 208-428"（有出处）必须放行
- 校验器只用真实数据测等于没测——必须证明它抓得住幻觉

## 复盘

意图对齐的高光不是写出多漂亮的 Prompt，而是把"大模型能不能识别报告"
这个方向性分歧，转化为一个双方都受益的架构：
大模型留下来了（表达层升级），风险被关掉了（数字全部本地定稿）。

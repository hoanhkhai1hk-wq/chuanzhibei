# 01 · 立项：选题调研、两次否决与 v2 定案

## 意图（用户原话，按时间顺序）

> 「找一下传智杯往年获奖的作品，分析一下，然后在GitHub上找项目二次开发」

> 「我是本科组B组别，现在找到的项目是做什么的」

> 「记住一点，要符合传智杯的赛题任务」

这一轮的关键不是某一句 prompt，而是**用户用一句话框死了约束边界**：
比赛、组别、可二开——三个条件同时成立，选题才有效。

## 约束与上下文（给 AI 的信息）

- 组别：B 组（普通本科），评审池与 985/211 不同，不能拿国一作品的技术高度当参照
- 官方 10 个推荐方向里没有健康类 → 需要论证"不违规"而不是硬靠
- 二开不等于套壳：严禁直接包装开源项目（官方黑名单）
- 执行者的能力基线：会 Python、不掌握前端与图像算法 → 方案不能依赖手写复杂前端

## 两次否决（这是意图对齐的核心证据）

| 版本 | 提案 | 否决理由 |
|---|---|---|
| v0 | CV Sandbox（数字图像处理实验室） | 执行者不掌握 OpenCV 与算法原理，答辩答不出原理就是灾难 |
| v1 | 《报告看得懂》纯报告解读 | **低频架空了卖点**：一年才体检一次，"多份报告对比"的差异化没有使用场景 |

v1 → v2 的转折点是一次反问："报告解读一年用一次，剩下的 364 天用户在哪？"
由此定案 v2《检后有伴》：**报告定义红线 + 高频日常记录对照**，
一句话定位"体检只占一年中的一年，剩下 364 天才是地盘"。

## 产出与验证

- 调研结论：往届国一作品实际只有 7 个 Python 文件、4 小时 25 连击 commit——
  竞争在"技术集成度与场景完整度"，不在代码量。这直接决定了 25% 过程分的策略
  （Phase 制留痕，不做焦虑式逐日打卡）
- 合规论证：官方措辞是"推荐选题方向"而非"必须"，评分标准五条无一提及方向 →
  判定健康类不违规，并在 README 主动写赛道符合性声明消除评委疑虑
- 落点：README 3.5 节、第十一章数据来源声明

## 复盘

这轮 Prompt 链的价值在于**否决也留痕**。多数参赛作品只展示"做了什么"，
不展示"为什么不那样做"——而意图对齐的深度恰恰藏在否决里。

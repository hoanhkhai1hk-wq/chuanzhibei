# 02 · 档案层：端到端串联（"串起来吧"）

## 意图（用户原话）

> 「串起来吧」

> 「先把你现在可以做到的，先做。我到时候需要我动手的，我再来搞」

四个字的一句指令。撑得起这四个字的前提是**前序 Prompt 已经把模块边界钉死**：
OCR 适配层、四元组解析器、指标字典、规则引擎各自独立成模块，
"串"只是把它们接起来，不需要重写任何一段。

## 约束与上下文

端到端链路在 Day 1 就被钉死为验收标准（README 3.5 节）：

```
图片 → OCR → 隐私脱敏(P0) → 四元组解析 → 字典归一 → 本地判定 → 红线
```

三条硬约束，全部来自此前踩过的坑：

1. **脱敏必须在解析之前**（P0）：若先解析再脱敏，患者信息可能已混进结构化结果
2. **数字只能来自本地**：OCR 抽取 → 字典比对 → 规则判定，任何一步不经过大模型
3. **验证逻辑与运行逻辑必须是同一份代码**：此前别名冲突事故
   （尿 WBC 覆盖血 WBC）的根因就是校验脚本和引擎各写了一套归一化

## 产出与验证

- `app/pipeline.py`：Pipeline.analyze() 串全链路，redact() 独立可测
- 测试策略（这轮的关键决策）：
  - **自洽性检查**：把 ground-truth 文本直接喂给解析器当"完美 OCR"，
    先排除解析器自己的 bug，再谈 OCR 识别率——两类错误混在一起根本查不动
  - 这个策略当场抓住了两个正则缺陷（66% 静默丢失率），省下的调试时间远超写它的成本

## 复盘

"串起来吧"能成立，靠的是**契约先行**：schemas.py 在任何业务代码之前落地，
19 个 Pydantic 模型就是模块之间的"接口宪法"。
Vibe Coding 里人最值钱的动作不是写指令，而是**把约束提前钉死**——
约束清楚之后，AI 四个字就能对齐；约束模糊时，四段话也会跑偏。

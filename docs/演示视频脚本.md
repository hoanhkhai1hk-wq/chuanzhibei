# 演示视频脚本（5-8 分钟）

> 目标评委：传智杯 AI 创新应用挑战赛（Vibe Coding 赛道）B 组
> 录屏前请先跑一遍「零、准备清单」，现场等 OCR 是最容易翻车的地方。

---

## 零、准备清单（开录前 5 分钟）

| # | 动作 | 命令 / 说明 |
|---|---|---|
| 1 | 启动服务 | 双击 `启动.bat`，或 `python -m uvicorn app.main:app --port 8000` |
| 2 | **清空数据库** | 删掉 `data/tjzh.db`（以及 `-wal` / `-shm`），保证第一份报告就是"首次使用" |
| 3 | 浏览器开两个标签 | 一个 `http://127.0.0.1:8000/`，一个 `http://127.0.0.1:8000/?tab=daily` |
| 4 | 关掉代理对本机的拦截 | 否则 `127.0.0.1` 会被拦成 502 |
| 5 | 录屏参数 | 1280×800 以上，全屏浏览器，缩放 100% |

> 为什么不用真实照片、改用「用演示数据试一下」：
> 演示模式现场合成报告、**一定会触发红线**，而且不上传任何真实个人信息。
> 录屏时用它最稳；真实照片的差异已在 `docs/真实样本实测.md` 里单独交代。

## 分镜表

### 1　开场 · 痛点（30 秒）

| 画面 | 旁白 |
|---|---|
| 首页，镜头停在标题 | 「一年体检一次，报告发下来那一刻你就看不懂了。而体检只占一年中的一天——剩下 364 天，那些异常项没人帮你盯着。」 |

**目的**：30 秒内把"低频报告"与"高频日常"的落差讲出来，这是整个产品的立论。

### 2　上传 → 七阶段思考可视化（60 秒）

| 操作 | 旁白 |
|---|---|
| 点「用演示数据试一下」 | 「先不上传真实报告，用一份现场生成的演示报告走一遍。」 |
| 镜头给进度条与右侧日志 | 「注意这里不是转圈圈等待。七步从上往下走：读取图片、OCR、脱敏、本地规则判定、数字回溯校验、写人话、红线与一周趋势。绿勾表示这一步真的做完了，转圈的是当下正在跑的那一步——下面日志每出现一行，都是后端实际返回的事实。数字全部在本地定稿，大模型只负责最后一步的措辞。」 |

**目的**：正对官方 UX 评分点原文「AI 响应状态提示友好（如流式、思考可视化）」。
**务必**让日志逐行出现的画面停留 3-4 秒。

### 3　结果页 · 逐项与可追溯（90 秒）

|---|---|

### 7　血压录入 → 自动激活限钠（45 秒）

| 操作 | 旁白 |
|---|---|
| 收缩压 150 / 舒张压 90 → 记录 | 「先录一次血压，150/90。注意提示：它自动激活了「限钠」红线。」 |
| 提示 toast | 「因为报告上根本没有血压——血压是测量值不是检验项，这条红线只能由日常层触发。阈值用《中国高血压防治指南》诊室标准 140/90，写在代码里。」 |

**目的**：日常层存在意义的最强证据，也是两层的连接点。
**顺序不能反**：必须先录血压激活红线，下一镜的那一餐才撞得到它。

### 8　记一餐 → 即时撞线（90 秒）

| 操作 | 旁白 |
|---|---|
| 搜索「火锅」→ 点选毛肚、午餐肉、啤酒 | 「吃火锅。点几下就行——食堂就那么几十道菜，点选比拍照稳，拍照不准会打断主流程。」 |
| 点「记录这一餐」 | 「立刻告诉你今天碰了几条线、碰了哪几道菜。全部本地累加，零模型调用。」 |

**录之前先看一眼「当前红线」有哪些**，再按下面这张表点菜，保证画面里一定有撞线结果：

| 想撞的红线 | 点这些菜 | 触发标签 |
|---|---|---|
| 限嘌呤 | 毛肚、午餐肉、三得利啤酒 | 嘌呤 high |
| 限钠 | 午餐肉 | 钠 high |
| 限酒精 | 三得利啤酒 | 酒 high |
| 限脂肪 | 红烧肉 | 脂肪 high |
| 补铁（绿色，方向相反） | 鸭血 | 铁，记「达标」 |

> 演示报告每次合成的结果不同，触发的红线也不一样——
> **按当前实际生效的红线挑菜**，比照抄这份脚本更可靠。

## 录制注意事项

1. **不要现场手动上传照片**：OCR 要跑 3-8 秒，录屏时很尴尬。一律用演示按钮，或 `?demo=1` 直达。
2. **切 Tab 要慢**：点击后内容异步加载，切过去立刻解说会撞上空白。
3. **红线一定要出现**：演示端点会主动挑选能触发红线的样本；如果你自己上传真实照片，可能一条都不触发，那这段就没素材了。
4. **`?tab=daily` 可以直达今日记录页**，省掉一次点击。
5. **补铁的绿色卡片一定要拍到**——这是唯一一条"方向相反"的规则，能证明不是无脑"要少吃"。

## 时长分配

开场 30s + 上传 60s + 结果 90s + 红线 60s + 家话 45s + 切 Tab 40s +
血压 45s + 记一餐 90s + 曲线 45s + 对比 60s + 架构 90s + 收尾 30s ≈ **10 分钟**

超时的话优先砍：结果页滚列表（-30s）、一周曲线（-45s）、开场（-15s）。
最低可压到 7 分钟，但**第 2 段（思考可视化）和第 7 段（血压激活红线）不能砍**——
那两段分别对应官方评分点与本项目最独特的设计。
另外**第 7 段与第 8 段的顺序不能调换**：先录血压激活限钠，那一餐才撞得到。

## 附录 · 可选段：问问 AI（30 秒）

**如果时长够，这一段建议插在第 4 段（日常红线 + 问诊清单）之后。**
它回答的是评委心里最可能冒出来的一个问题：
「这不就是把报告讲一遍吗，跟直接问 AI 有什么区别？」

| 操作 | 旁白 |
|---|---|
| 滚到红线卡片下方的「问问 AI」 | 「这里可以直接问。注意上面这行小字：基于你的报告回答，已脱敏，不编数字。」 |
| 点「我今天能吃火锅吗？」 | 「它没有去猜。先从本地菜品库里认出火锅类里有哪些菜，再拿你当前的红线逐条比对——牛肉卷、羊肉卷、虾滑标的是高嘌呤，撞上的就是你那条限嘌呤红线。撞没撞线是本地算的，不是模型随口说的。」 |
| 指一下回答下面那行小字 | 「`本地生成`、`数字全部来自本地 · 2 个`——这次回答里出现的每个数字都能溯源。」 |
| 在输入框里打「我叫张三，身份证 1101…，我这个要复查吗？」并回车 | 「提问里就算打了身份证，也会在送出去之前被抹掉，下面这行 `已抹除：身份证、姓名` 就是证据。」 |
| 再点「尿酸高是怎么回事？」（若本次报告没有尿酸） | 「报告里没有这一项，它会直接说没有，而不是编一个数给你。」 |

**这一段的杀伤力在哪**：市面上的「AI 问诊」在第三秒就开始编数字。
这里能当场演示「它拒绝编」——这比任何架构图都有说服力。
